# Commit 2026-11-22: modules, records, and intake terms

This commit does three things. It fixes the module set and the two cross-cutting attributes.
It fixes the three records that a deliverable can emit, with schemas and examples that pass
their own validator. It fixes the terms on which a party hands over files, including which
fields have to arrive with them.

Normative files: `POSITIONING-CLIENT-zh.md` (client-facing, Chinese), `PEV_RECEIPT.md`
(records and matrix, English), `DATA_TERMS.md` (partner intake, English). The diagram is
generated from `matrix_diagram.py`, not edited by hand.

## What changed

| Area | Change |
|---|---|
| Module name | M1 renamed from precision budget to **sample budget**. What the module decides is how many attempts, configurations and cells; the target interval width is a C-column criterion, not the module name |
| Diagram | redrawn as two timelines plus two cross-cutting bands, replacing the table-like layout. The dashed cut marks 开跑 → 收工; module boxes span both bands |
| Temporal constraint | rewritten as an **instrumentation** constraint: the process metadata has to be captured at the time. Five fields are listed with why each cannot be rebuilt. M1 and M2 are embedded; M3 and M4 are late arrivals by design |
| Criterion column | domain transfer added as a hard rule: rho is not borrowed across strata (0.4841 to 0.8167 on one snapshot; 0.0827 against an assumed 0.5, roughly sixfold). Assessor-ranking work splits inter-rater agreement from within-unit clustering |
| Columns | both column headers are now questions: *can these two numbers be compared*, and *what is delivered, at which level, with what proof* |
| PEV record | `claim_under_test` must quote the claim **verbatim**, with `claim_locator` naming where the quotation sits. `not_verified` must be present and may be empty; omission is invalid |
| Third schema | `eval-log-min.schema.json` added: one object per attempt, ten required fields, enumerated termination reasons and scoring methods, `init_state_digest` constrained to 64 hex characters |
| Intake terms | `DATA_TERMS.md` gains "What to send: files, not links" and "Required attempt fields". A link is not an input; an aggregate table alone caps the work at L1 |

## Why two of these are not cosmetic

A quoted claim that is paraphrased quietly changes what is being checked. A missing
`not_verified` key reads as coverage that does not exist. Both are silent failures, which is
why the schema rejects them rather than leaving the rule to prose.

The same reasoning applies to intake. A URL resolves to different bytes on a second request
and nothing about that appears in a certificate; an aggregate table cannot support trace
verification or reproduction at all. The clause therefore requires a file, a hash on arrival,
and a declaration naming the fields that were never captured.

## Validation

```
python3 governance/schema/validate.py governance/schema/examples/pev-example.json
python3 governance/schema/validate.py governance/schema/examples/receipt-example.json
python3 governance/schema/validate.py governance/schema/examples/eval-log-example.json
```

All three pass, exit 0. Negative cases are constructed by copying an example and changing one
field. Eight cases are rejected, exit 1, including `not_verified` removed, `bytes: 0`,
`claim_locator` removed, `result: "pass"`, `borrowed_from` with an empty note, `seed` removed
from a log attempt. All three schemas pass `Draft202012Validator.check_schema`.
