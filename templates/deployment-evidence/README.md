# 部署证据清单

用途：把"某款机器人在真实场景跑得怎么样"从宣传语变成可核的记录。清单只记录，不做推荐，不给认证。

## 一、为什么需要

公开的具身数据几乎都是评测场景：固定台面、固定任务集、短时运行。真实部署关心的是另一组量：连续运行多久、失败几次、人介入了多少次、介入算不算失败。这些量目前没有独立来源，只有厂商自述。

## 二、字段

| 字段 | 含义 | 必须写清什么 |
|---|---|---|
| product | 产品名 | 型号，不是系列名 |
| scenario | 场景 | 地点类型与作业内容，例如"零售补货" |
| task_set | 任务集 | 有哪几类任务，各自占比 |
| continuous_hours | 连续运行时长 | 单次连续，不是累计 |
| attempts | 尝试次数 | 分母，必须与 successes 同一口径 |
| successes | 成功次数 | 判定标准谁定的、写在哪 |
| significant_failures | 显著失败 | 定义写进备注，例如造成中断或需人工复位 |
| human_interventions | 人工介入次数 | 远程接管、现场复位、重试 分别计 |
| denominator_defined | 分母是否写明 | 是/否 |
| intervention_counted_as_failure | 介入是否计入失败 | 是/否 |
| log_available | 是否有可查日志 | 链接或"无" |
| continuous_video | 是否有连续未剪辑视频 | 链接或"无" |
| third_party_present | 是否有第三方在场 | 机构名或"无" |
| claim_text | 声明原文 | 逐字抄，不改写 |
| claim_source | 声明出处 | 链接与日期 |
| evidence_grade | 证据等级 | 由对照表判定，见第四节 |

## 三、口径必须先定

以下三条在填表前写成一句话，全表照此执行，不得中途换口径。

**分母（一次尝试）**：一个任务实例从开始执行到判定结束，计为一次尝试。中途接管、复位、重试都不新开计数；同一实例上第二次执行，仍记在该次尝试之下，并在备注里说明曾经中断。分母必须与 successes 用同一口径，否则两个数不能相除。

**接管（takeover）**：操作员在任务执行过程中取得控制权并完成剩余动作，计为一次远程接管。接管与“现场复位”“人工重试”是三种不同成本：接管发生在任务中途，该次尝试即判定失败；现场复位指机器人停机后由人恢复位姿再继续，同样判该次尝试失败；重试指同一实例重新起始，属于新的一次尝试，单独计数。

**成功**：判定者写清是谁——厂商自评、第三方评、自动评分，三者不可混计；判定标准写进备注，不超过一句。

分母：一次尝试指什么。抓取动作算一次还是整个任务算一次，必须在填表前定，全表一致。

成功：判定者是谁。厂商自评、第三方评、自动评分，三种要分开写。

介入：远程接管与现场复位是两种成本，不能合并成一个数。介入如果发生在任务中途，该次尝试计为失败，除非另有说明。

缺失：没有记录就留空，不要填零。空与零在统计上不是一回事。

## 四、证据等级

| 等级 | 条件 |
|---|---|
| A | 有日志、有连续视频、有第三方在场，分母写明，介入计入失败 |
| B | 有日志，分母写明；缺第三方或连续视频之一 |
| C | 自述数字，分母与介入口径至少缺一项 |
| D | 只有宣传语，无日志、无分母 |

等级只描述证据形式，不评价产品好坏。同一产品在不同场景可以有不同的等级。

## 五、怎么用现有工具审计

分母一致性与成功率区间：把 attempts 与 successes 代入 ReDA 自查表，得到该样本量下能分辨的最小差距。样本太小时，"89% 成功率"与"76% 成功率"可能分不开。

介入成本：把 human_interventions 除以 attempts 得介入率，与成功率并列报告。只报成功率不报介入率，等于把人力成本藏在分母外。

证据连续性：日志时间戳是否覆盖所声明的连续时长；视频是否一段到底。断点即降级。

## 六、边界

不做产品推荐。不做安全认证。不替代合规评估。厂商未公开的记录留空，不推测。发现与声明不符时，只记录差异，不判断动机。
